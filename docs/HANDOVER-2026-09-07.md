## YOURS — do these, they are not fixable from the repo

### 1. DNS at Spaceship (skopnix.com) — the highest-value 10 minutes here
Right now **anyone can send mail as `hello@skopnix.com`** — the address printed
in `/.well-known/security.txt` — and **no mail sent to it can ever arrive**,
because the domain has no MX at all. For a threat-intel brand whose product is
trusted attribution, a forged "skopnix advisory" is the cheapest possible attack.

Add these records exactly:

| Type | Host | Value |
|---|---|---|
| TXT | `@` | `v=spf1 -all` |
| TXT | `_dmarc` | `v=DMARC1; p=reject; adkim=s; aspf=s; fo=1; rua=mailto:<a mailbox you read>` |
| TXT | `*._domainkey` | `v=DKIM1; p=` |
| MX | `@` | priority `0`, value `.` (RFC 7505 null MX) |
| CAA | `@` | `0 issue "letsencrypt.org"` |
| CAA | `@` | `0 issuewild ";"` |
| CAA | `@` | `0 iodef "mailto:<a mailbox you read>"` |

Then EITHER stand up real inbound mail (and relax SPF to that provider's
`include:`) OR change the `Contact:` line in `public/.well-known/security.txt`
to an address that receives mail. Do not leave both as they are.

Also enable **DNSSEC** in the Spaceship panel. Without it and without CAA, a DNS
hijack converts straight into a valid certificate from any of ~130 CAs.

## DONE — website

**Honesty and claims**
- "sensor-backed in the Caucasus" appeared in the footer, the site description
  and the OG card with no sensor data anywhere on the site. Reworded to what
  actually exists: a weekly internet-exposure census.
- The early-access promise contradicted the API docs ("keys for the full API"
  vs "no key, no account"). One concrete promise now, everywhere: actor API +
  MCP, alerts, STIX export.
- `attribution confidence 50/100 (source-stated)` sat on nearly every dossier.
  MISP states a literal "50" on ~150 actors as its unassessed midpoint; it is
  no longer rendered as if it were an assessment.
- Weak "semantic match only" similar-actors dropped below 0.8.
- The masthead and the kill chain counted tactics differently. One shared
  `lib/attack.ts` now.

**Correctness**
- Real 404s again: `app/loading.tsx` streamed a 200 before `notFound()` ran, so
  `/news/<junk>` and `/actors/<junk>` were soft-404s.
- Per-CVE KEV truth in the API. A Patch-Tuesday roundup naming 400 CVEs was
  `kev:true` because of one of them; `kev_cves` and `cves[{id,kev}]` say which,
  and `roundup` flags 20+ CVE lists.
- `/api-docs` described a category enum that never existed.
- Alias dossiers (UNC2452) no longer appear as separate "on the wire" rows from
  their canonical actor (APT29).
- English category glyphs on English pages (VULN/EXPL/… not ZF/EK/…).
- EPSS 0.996 rendered as "100%"; shows 99.6% now.
- Emoji stripped from headlines; MISP walls of text split into paragraphs.
- The "on the wire" panel announced 12 adversaries and showed 2 — the row
  stagger had no ceiling, so the last row started at 1.12s.

**New**
- `/cve/CVE-YYYY-NNNN` — a hub per CVE: KEV with the date added and ransomware
  use, EPSS with percentile, CVSS from NVD, the exposure census, every dispatch
  that named it, and the adversaries those dispatches named. This was the
  analyst reviewer's single most-wanted feature.
- `/api/v1/actors` and `/api/v1/actors/{id}`.
- `?before=` cursor with `next_before`; 400 on an unknown category; weak ETags
  with 304 on `If-None-Match`.
- `/.well-known/security.txt`; sitemap covers every non-alias dossier plus the
  400 most recent CVE hubs (2,205 URLs, was 1,243).
- `/actors` roster rendered as one escaped string: 1.03 MB → 745 KB.

**Security (from the pentests)**
- The proof-of-work was forgeable offline in 14 ms — constant key in the bundle,
  no binding to the caller. Key from `POW_SECRET` when set, challenges signed
  per caller network (IPv4 /24, IPv6 /48), difficulty 16 → 18 bits, client loop
  yields every 4k hashes. The copy no longer claims the list "can't be
  scripted", because at any browser-tolerable difficulty that is false.
- The admin session cookie's value was a constant HMAC with no timestamp, so a
  copy from a log stayed valid until `ADMIN_TOKEN` rotated. It now carries an
  issued-at that `isAdmin()` enforces (7 days).
- `robots.txt` named `/admin`; the sign-in card explained its own auth design.
- Share cards rendered per request uncached, and unknown slugs still rendered a
  PNG. Unknown → 404; real → one year immutable.
- `/api/hit` is unauthenticated and writes to your only analytics dataset;
  `path`/`ref`/`src` are shape-checked now.

## KNOWN, NOT FIXED

- **CSP keeps `script-src 'unsafe-inline'`.** No reachable inline-injection sink
  exists today (every HTML sink is escaped), so this is latent. A real fix needs
  nonces via middleware, which this project deliberately avoids for its
  per-request cost. Revisit if any raw-HTML sink is ever added.
- **The rate limiter is per-serverless-instance.** A rotating-IP or
  multi-instance caller is not bounded by it. `lib/ratelimit.ts` already has an
  Upstash-backed path — set `UPSTASH_REDIS_REST_URL` / `_TOKEN` to switch the
  waitlist and beacon onto a shared counter.
- **Stories are still mostly RSS ledes** (106 of 200 truncated) and 64 of 97
  vuln items carry no CVE because extraction reads the feed lede, not the
  article body. This is the biggest remaining quality gap and it is an engine
  change, not a website one.
- **Dossier roster cruft.** `/actors/agl0bgvycg` is base64 "hitler"; some
  ransomware.live stubs carry an engine-written brief. A quality gate (ATT&CK or
  MISP id, or ≥2 sources) would cut the "1,373 dossiers" number and raise it.
- **The archive has a five-day hole, 22–31 Aug.** Worth a public status page.
